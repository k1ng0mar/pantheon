# Run a task on another computer

## Remote access

- **Choose the computer beside Local and Worktree.** Once you're signed in to PandaCode Connect, the bar above the prompt box lists *This computer* and your trusted, online computers. Pick one and send: the task runs there, and everything else works exactly like a local task: the same sidebar row, transcript, streaming, queue, Stop, approvals, model and permissions. The separate Computers section and remote view are gone.
- **The other computer gets the project for you.** It opens the same GitHub repository if it already has it, or clones it into `~/PandaCode`, then uses the same branch. With Worktree it works in a fresh worktree, and it never switches a checkout that has uncommitted changes or a running agent.
- **You're warned when GitHub is behind.** If this computer has unpushed commits, uncommitted changes or an unpushed branch, PandaCode tells you the other computer will start from GitHub's version and asks before continuing.
- **Fast and light.** The other computer pushes its agent's output about ten times a second at most, and messages are copied once per run, so nothing polls.

## Fixes

- **Fixed "Could not read this computer's PandaCode Connect key from Keychain (-25293)".** It happened when two PandaCode builds on one Mac shared a keychain entry. Each install now has its own entry; sign in to remote access once more after updating.

## Known limitations

- Images and browser captures can't be attached to a task that runs on another computer yet.
- Changes, diffs and commits for a remote task stay on the computer that runs it.
- Remote access has been tested with automated tests only, not yet between two real computers.
