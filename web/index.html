One runtime, every hard part

Full tour →

Runtime authority

The model requests; the runtime decides. Capabilities, policy, and approvals are enforced in code — never in prompts.

Event-sourced ledger

Every turn, tool call, and approval is a SQLite row. Inspect it, replay it, audit it — offline.

Crash recovery

Kill the process mid-run. The next turn resumes from committed state — finished calls skipped, interrupted ones re-driven.

Durable approvals

Gated calls park the run safely. Answer inline, or out of band from another terminal, script, or chat app.

Memory with trust

Layered, provenance-tracked memory behind a policy gate. The model can never promote its own guess.

Every surface

Terminal, local web, Discord, Telegram — one agent, one history, whichever screen is nearest.

Questions

▸ Do I need Rust, Node, or Docker to install?

No. The installer downloads a prebuilt binary and needs only curl and tar. Rust is only required to build from source; SQLite is bundled, so there is no database to run.

▸ Which models does it work with?

Any OpenAI-compatible endpoint or Anthropic, plus custom URLs via pantheon provider add. The agent never picks models — the runtime resolves a default, a failure-only fallback chain, and per-job helpers. See Providers.

▸ Where does my data live?

On your machine: ~/.pantheon (or $PANTHEON_DATA_DIR) holds the config, key store, ledger, and memory. No hosted control plane, no account, nothing phones home.

▸ What happens when a tool call needs permission?

The run parks durably and asks — inline in the session, or via pantheon run --grant/--deny from anywhere, including chat buttons. Denials become transcript text, not crashes.

▸ How do I update?

pantheon update fetches the latest GitHub release for your platform and swaps the binary, keeping a backup. --check reports without changing anything.
