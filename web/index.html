The hard parts, handled

Full tour →

It asks first

The model proposes, the runtime disposes. Capability checks, policy, and approvals are enforced in Rust, not suggested in a system prompt.

Everything is written down

Every turn, tool call, and approval lands as a typed row in SQLite. Query it, replay it, hand it to an auditor. No network required.

Survives a crash

kill -9 the process mid-run. The next turn resumes from committed state, finished calls skipped, interrupted ones re-executed. Nothing lost, nothing run twice.

Approvals that wait for you

A gated tool call parks the run instead of blocking it. Approve from the terminal, a script, or a chat button. Either way the decision lands in the ledger.

Memory it can't fake

Five memory layers, provenance on every record. The model can propose memories. Only you, or your policy, can promote them.

One agent, every screen

Terminal, web, Discord, Telegram. One agent, one ledger, whichever screen is closest.

Common questions

▸ Do I need Rust, Node, or Docker to install?

No. The installer fetches a prebuilt binary and needs only curl and tar. Rust is only for building from source; SQLite is bundled, so there's no database to install or run.

▸ Which models does it work with?

Any OpenAI-compatible endpoint or Anthropic, plus custom URLs via pantheon provider add. The agent never chooses its own model: the runtime resolves a default, a failure-only fallback chain, and per-job helpers. See Providers.

▸ Where does my data live?

On your machine, full stop: ~/.pantheon (or $PANTHEON_DATA_DIR) holds the config, key store, ledger, and memory. There is no hosted control plane, no account, nothing phoning home.

▸ What happens when a tool call needs permission?

The run parks, durably, not blocked, and asks. Answer inline in the session, or from anywhere with pantheon run --grant/--deny, including chat buttons. A denial becomes transcript text, not a crash.

▸ How do I update?

pantheon update fetches the latest GitHub release for your platform and swaps the binary, keeping a backup of the old one. --check reports what's available without changing anything.
