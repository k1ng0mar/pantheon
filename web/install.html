INSTALL

A minute to a working agent.

A prebuilt binary from GitHub Releases. The installer needs only curl and tar — no Node, npm, Git, Python, Rust, or Cargo. Re-running never overwrites your config.

curl -fsSL https://raw.githubusercontent.com/k1ng0mar/pantheon/master/install.sh | bash
iwr https://raw.githubusercontent.com/k1ng0mar/pantheon/master/install.ps1 -useb | iex 
git clone https://github.com/k1ng0mar/pantheon.git
cd pantheon
cargo build --release   # binary: target/release/pantheon

Requires a Rust toolchain (edition 2021). SQLite is bundled — no database to run.

Pin a release: PANTHEON_VERSION=v0.1.0 bash install.sh. Prefer a package? Grab the asset for your platform from GitHub Releases.

What the installer does

Four explicit stages. A failure names its stage — and a runtime-probe timeout says exactly that, never disguised as a failed install.

[1/4]

Checking environment

Detects OS and architecture, confirms curl and tar. Nothing else required.

[2/4]

Installing Pantheon

Resolves the release, downloads the binary, verifies the checksum, links into ~/.local/bin.

[3/4]

Initializing

Creates ~/.pantheon, writes a default config only if none exists, prepares storage.

[4/4]

Verifying installation

--version, runtime probe, config check, storage check — each reported on its own.

Then point it at a model

pantheon setup --yes \
  --provider openai \
  --model gpt-4o-mini \
  --api-key-env OPENAI_API_KEY

export OPENAI_API_KEY=sk-...
pantheon
  • pantheon setup — five questions, or all flags with --yes. Config stores the key's name, never its value.
  • pantheon doctor — exit 0 means config, key, ledger, memory, and plugins are healthy. Failures name their fix.
  • pantheon update — latest release for your platform, with a backup kept. --check reports without changing anything.
